## 安装与管理

新安装优先使用下方一键脚本。执行前审阅脚本；其默认获取最新稳定 Release，明确指定 `BRANCH` 时使用该版本，并以 root 执行下载代码。安装会修改系统软件包、转发、PPP/L2TP、防火墙与服务。需要从已审阅源码工作副本安装时，参阅[开发指南](development.md)；现有安装请使用下方更新流程。

安装：

```bash
curl -fsSL https://raw.githubusercontent.com/lucaswren/s2l/main/script/remote_install.sh | sudo bash -s -- --lang zh-Hans
```

安装语言统一使用 `--lang`：`en`、`zh-Hant`、`zh-Hans`（默认）。一键安装可在 `sudo bash` 后加 `-s -- --lang zh-Hans`；源码安装使用 `sudo bash script/install.sh --lang zh-Hans`。内核检查、失败恢复及 HTTPS 配置会沿用此语言；APT、Go 等外部工具保留原始诊断。内核重启后请使用相同参数重新安装。

Nginx 已合并至首次依赖安装，HTTPS 阶段不再重复下载 APT 软件包。`[TIME]` 分别显示依赖、Go 准备、编译、证书及服务验证耗时。Go 首次编译也会构建标准库，并显示包名供查看进度；后续编译沿用缓存。编译速度仍取决于 CPU、内存及磁盘。

修改 SOCKS5 地址、账号或密码时，会先列出必须停止的关联映射，包含等待清理的错误状态映射。表单保留，不会自动停止或重启映射；名称与分组可在线直接保存。停止列出的映射后返回保存，再按需启动。

主推环境维持 Ubuntu Server 24.04 LTS amd64。Debian 12 是兼容性测试目标，换系统无法消除首次编译与软件下载成本。截至 2026 年 10 月，[Debian 12 已进入 LTS，至 2028 年 6 月结束](https://www.debian.org/releases/bookworm/)；[Debian 13 支持期更长](https://www.debian.org/releases/trixie/)，但尚未通过本项目完整虚拟机验证。

引导脚本检测到 curl、Git、Python 与 CA 证书库均可用时，跳过引导阶段的 APT 操作；安装器仍会检查及安装运行依赖。无效路径／分支及活动隧道服务在下载前拒绝。已有源码目录必须符合指定来源且没有本地修改（含未跟踪文件）；请先保存文件或指定新的绝对路径 `SRC_DIR`，不会自动重置。并发下载使用独立锁。

### SOCKS5 节点与映射导入

SOCKS5 文本导入仅在地址、账号、密码完全相同时复用节点；相同地址使用不同凭据会建立独立节点，避免覆盖供应商以账号区分的出口。重复导入未命名节点会保留原名称与分组。修改已有凭据请用编辑，或明确指定 ID 的 JSON 导入，并先停止关联映射；完全相同但重复存在的节点会要求指定 ID。

特殊字符或有歧义的纯数字密码，建议使用 `socks5://user:password@host:port` 并将凭据百分比编码：`@` 写成 `%40`、空格写成 `%20`；IPv6 地址加方括号。JSON／URL 保留凭据空白；分隔文本会去除字段前后空白，不支持引号包裹分隔符。多余字段、URL 路径及查询参数会拒绝，批次结果逐行显示错误，全部失败时也保留诊断；有效行仍会保存。

映射可使用唯一节点名称、唯一地址或明确 ID；重名或共用地址时须指定 ID。文本重复导入保留分组与网络调优，映射须先停止；JSON 导入使用提交字段。

### 防火墙范围与端口

S2L 管理 PPP/TUN 转发防护，不是完整的公网主机防火墙。INPUT 默认 ACCEPT 不会限制公网 SSH／HTTPS；管理入口应由主机商安全组或已审阅的主机规则限制。改变当前管理路径前，须有可用的恢复控制台。

| 流量 | 放行范围 |
|---|---|
| 管理 | 现有 SSH TCP 端口与指定 HTTPS TCP 端口，限制可信管理来源 |
| 普通 L2TP | 预期客户端的 UDP 1701 |
| L2TP/IPsec | UDP 500/4500；未经 UDP 封装时的 ESP；UDP 1701 仅在设置的 IPsec 策略下放行 |
| 后端 | 仅 127.0.0.1:8080，不向公网放行 |

健康检查会发现被前方规则遮蔽的 S2L 入口，恢复顺序而不清空其他规则。同一地址族的 filter 变更一起提交，PPP 管理例外保持优先。这是周期修复，不能保证抵抗持续竞争的防火墙管理器或另一套原生 nftables 基础链。请保持一致的 iptables 后端，避免多个工具同时改写规则。PPP 子网通过 TUN 路由，不桥接到主机 LAN，因此生成的 PPP 选项移除 proxy ARP；现有连接须重连才会采用新选项。

### 内核与首次安装

首次安装在部署 PPP/S2L 前自动检查内核：Ubuntu `6.8.0-146-generic`、`6.8.0-147-generic` 存在已知 L2TP 回归，也会检查 `/boot` 中已安装的最高版本 generic 内核，避免下次重启进入已知问题版本。默认 `S2L_KERNEL_UPGRADE=auto`：仅在专用新主机、Ubuntu 24.04、标准 GRUB 默认启动项下，从系统 APT 源准备 `linux-generic-hwe-24.04`。会检查空间、内核镜像、initramfs、GRUB 启动项及 PPP/L2TP/TUN 模块，不加载新模块、不重启、不删除旧内核，也不部署 S2L。

内核准备成功后以 **退出码 20** 结束，表示“等待人工重启”，不是安装成功。确认控制台回退入口及维护窗口后手动重启，检查 `uname -r`，再用**原参数**重跑安装命令；未重启重跑时，会检查并复用已准备好的内核。没有自动续装服务，不保存管理密码或安装参数。安装的软件包不属于 S2L 安装回滚范围。APT 失败、目标文件不完整或仍是问题内核时拒绝继续。设置 `S2L_KERNEL_UPGRADE=off` 可关闭自动准备，但不能绕过问题内核检查。Debian、其他 Ubuntu 版本、自定义引导和现有安装均不会通过此流程自动升级内核；参阅下方手动方案。未命中已知版本仅表示不在当前拒绝名单，不代表所有内核都经过验证。

新服务器安装会**自动启用 HTTPS**，默认使用有效期 **365 天** 的自签证书，无需申请公网证书。访问管理界面需放行 HTTPS 管理端口；实际拨号还需按所选模式放行隧道端口。成功后显示 `https://服务器IP:端口`、管理账号与 **16 位随机密码**。HTTPS 管理端口随机选择 **10000-60000** 范围内的空闲端口，内部后端固定监听 **127.0.0.1:8080**，SSH 端口保留现有设置；自定义密码至少 **12 位**。

公网 IPv4 默认自动识别；需指定时，将安装命令末尾的 `sudo bash` 替换为 `sudo env PUBLIC_IP=服务器公网IPv4 bash`。后端端口无需指定，也无需对外放行；HTTPS 端口不能使用 8080。使用 `HTTPS_PORT` 指定 HTTPS 管理端口，例如：

```bash
curl -fsSL https://raw.githubusercontent.com/lucaswren/s2l/main/script/remote_install.sh | sudo env HTTPS_PORT=8443 bash -s -- --lang zh-Hans
```

请提前放行 TCP 8443；不指定时，安装过程显示随机 HTTPS 端口，需放行后才能访问。

1. 使用安装时显示的 HTTPS 地址登录。
2. 添加 SOCKS5 节点，创建映射，启动至 `running`。
3. 客户端选择 L2TP，填写服务器 IP 和映射账号密码；默认不启用 IPsec。

节点列表点击“上下行测速”，分别显示下载、上传速度与连接延迟。测速由服务器经所选 SOCKS5 节点访问测速站，默认每个方向传输 5 MB；单向失败会保留另一个方向的结果。

网页“系统设置”可修改管理用户名、密码、HTTPS 端口和 SSH 端口，登录后无需再次输入管理密码。新密码至少 12 位，留空则只修改用户名；账号修改立即生效，无需重启服务。修改 SSH 前先放行新 TCP 端口，成功后用 `ssh -p 新端口 用户名@服务器IP` 验证登录。

网页“系统设置 → SSH 登录密码”可修改 root 的 Linux 登录密码，仅允许已登录管理员通过 HTTPS 操作，确认新密码即可，无需再次输入管理密码。支持生成 16 位随机密码，手动密码至少 12 位（最多 128 位可见 ASCII 字符）。修改后保留原 SSH 连接，在新终端验证登录；此操作不启用密码登录、不解除账号锁定，也不修改网页管理密码。

网页“系统设置”可启用 **L2TP/IPsec（IKEv1 + PSK）**，适用于支持该模式的 L2TP 客户端。密钥至少 12 位，所有映射共用；留空保留现有密钥，列表不会返回密钥。启用前放行 UDP 500、4500；本项目统一使用 NAT-T 封装，无需单独放行 ESP，客户端填写相同 PSK；开启后服务器阻止普通 L2TP 接入。关闭后客户端清空 PSK。切换模式或更换密钥需重新拨号。配置或防火墙操作失败时会尝试回滚；若恢复失败，需通过 SSH 检查。备份为 `/opt/s2l/ipsec-backup.json`。与已有 IPsec 服务冲突时会拒绝修改。具体兼容性需按客户端版本验证。

IPsec 防护状态会核对 INPUT、OUTPUT 专用链的完整规则和安全顺序；重新应用设置或重启服务时原子修复两端防护。OUTPUT 阻断没有 IPsec 策略的 L2TP 回包，包括会话隔离辅助程序故障时的回包。同一 NAT 下客户端可保留源端口 1701，见[接入要求](clients.md)。

updown 辅助程序在 `/run/s2l-ipsec-nat` 记录自有规则、串行处理并发通知，并只删除退役安全关联的连接跟踪条目；服务启停清理遗留规则。只有对应安全关联的隔离规则准备就绪后才接收解密后的 L2TP；早到包在连接跟踪确认前丢弃，防止重新拨号缓存未转换的对端端口。修复静态防火墙时保留正在使用的会话放行规则。

专用主机须为 S2L 保留连接跟踪区 20000–65535；内部对端端口不是公网监听端口，不要在安全组放行。退役端点进入可复用池，正常重拨不再永久消耗累计 45,536 次的额度。新安全关联到达时，分配与回收共用进程锁自动执行：先移除旧关联的准入、路由规则和连接跟踪，再隔离至少 30 秒；相隔至少 2 秒的两次空闲观察必须核对 xl2tpd 全局与 LNS 隧道清单一致，覆盖未完成协商的隧道，并确认无旧端点套接字、L2TP 待处理报文、关联 XFRM 状态/策略及连接跟踪区条目。XFRM 使用 reqid/mark 和退役时未标记入站 SA 的 SPI 快照区分连接代际，避免把复用 reqid 的新连接误判为旧关联残留；仅记录 SPI/地址元数据，不保存密钥。在线客户端保留原端点和固定 SOCKS5 映射。

45,536 现在是活动端点与尚不能安全回收端点的容量上限，不是累计成功重拨次数。池满但已有安全候选时，当前拨号会等待短暂的第二次核验；无法确认安全则拒绝新会话。查询失败或 xl2tpd 状态格式不受支持时保留端点，并在 `/run/s2l-ipsec-nat/state.json` 中记录 `reclaim_error`，不会强制复用。已实测 xl2tpd 1.3.18；要求 root 所有的 `/run/xl2tpd/l2tp-control` 及完整的全局/LNS 状态接口，自定义 LAC 配置保守地不参与回收。回收按新关联需求触发，空闲期间保留退役记录属于正常行为，不能手动删除运行状态。旧版状态缺少退役身份时保留原分配区间，直到两套协议栈均停止；正常升级脚本已经按此顺序停止和启动服务，可安全完成迁移。

升级保留 IPsec 启用及运行状态，并在服务启动时刷新生成的配置；缺少的 `conntrack` 会按升级章节自动补装。

Ubuntu 使用软件包附带的 charon AppArmor 配置时，IPsec 启动仅在 `/etc/apparmor.d/local/usr.lib.ipsec.charon` 增加对 `/opt/s2l/ipsec.secrets` 的读取权限并重载配置，保留其他管理员规则和强制约束。自定义配置不受支持或重载失败时拒绝启动 IPsec；这条精确读取规则会保留，供重试及旧版本使用。

普通 L2TP 需在安全组放行 UDP 1701。管理页面能修改网络并查看凭据，请限制 HTTPS 管理端口的来源 IP。

配置：`/opt/s2l/config.json`；运行数据：`/opt/s2l/data/state.json`。数据文件含代理和拨号凭据，请限制访问权限。

## 上游健康与防泄漏

TUN 回程仅放行到对应网段、经 PPP 接口返回的已建立或相关连接。PPP 断开导致客户端路由消失时，迟到回包在转发层丢弃，不能经服务器默认出口发送。每个受管 TUN 的回程入口与终止丢弃规则保留至主机重启，映射停止时仅撤销放行；同一接口反复重拨不会累计规则。升级清理旧的宽泛放行规则，健康检查可原位恢复缺失的回程防护。

映射 `running` 与上游健康分别显示，TCP、UDP、DNS 各自检查：

| 项目 | 实际探测 | 结果含义 |
|---|---|---|
| TCP | 经 SOCKS5 认证与转发获取小型 HTTPS 响应；Cloudflare 与 Google 为替代目标 | 可通过上游访问探测网站 |
| UDP | SOCKS5 `UDP ASSOCIATE`，再经协商出的中继向 `1.1.1.1:53` 或 `8.8.8.8:53` 发送 DNS 数据报 | 响应须匹配来源、查询 ID 与问题；忽略分片及无效响应。仅明确的 SOCKS 响应码 7 标为不支持 |
| DNS | 经 SOCKS5 探测配置的 DoH，自动模式失败后探测配置的 TCP DNS；默认为 `https://1.1.1.1/dns-query` 与 `8.8.8.8:53` | 主 DoH 成功为正常；仅 TCP DNS 成功时显示“仅备用可用”，探测状态与实际解析器分开显示；自动 DNS 模式按真实查询失败切换 |

DNS 探测查询公开名称 `example.com`，目标流量均使用选定代理，不直接回退到 DNS 目标。建立上游连接时，代理或中继主机名称仍可能需要服务器自身解析器。提供商会收到这些探测连接与查询；健康检查不读取或上传客户端 DNS 历史。

协议首次失败标为不稳定，连续三次失败为不可用，连续两次成功才恢复正常。UDP 明确不支持与 DNS 仅备用可用分别标示。TCP 可用但 UDP/DNS 有问题时显示部分可用，不判为整个节点中断；其他成功探测也避免一概显示不可用。保留 L2TP，这些协议探测失败不会触发 sing-box 重启。

健康状态每 45–55 秒检查，首次与故障确认使用较短间隔，另加探测与调度时间。TCP 失败按 5、10、20、40、最多 60 秒退避，部分可用时可维持正常间隔。最多同时处理四条映射，每条的协议探测并行且各有时限。拒绝 UDP 的映射跳过自动 UDP 探测；不支持或持续不可用时每 10 分钟复测。结果不验证本机 TUN/L2TP 客户端路径、所有 DNS 名称、DNSSEC、QUIC 或所有 UDP 应用。

上游中断时保留 L2TP，已失败的应用连接需要重新建立。sing-box 进程或 TUN 消失时，以受限频率自动恢复，不停止 L2TP；失败显示在健康状态与服务日志中。目前不自动切换其他节点；更换映射节点前先停止映射。运行中映射使用的节点不可修改连接设置。

S2L 必须使用专用主机：持续防护覆盖**所有 `ppp+` 接口**。PPP IPv4 仅允许已配置来源子网经对应 TUN 转发；其他转发及 PPP 对服务器本机的访问均丢弃，明确配置的本机管理访问例外除外，PPP IPv6 也被阻断。TUN 消失时，终止查找的不可达路由阻止回退到主路由表。停止 S2L 或映射后仍保留阻断规则，避免现有 PPP 连接从主机出口绕行。`s2l-guard.service` 在 xl2tpd 前安装规则，失败时阻止 xl2tpd/S2L 启动。不要清空这些规则或让其他防火墙管理器覆盖。客户端分流与其他网络接口不在服务器控制范围内。

## 升级

### 一条命令准备内核（Ubuntu 24.04）

在包含此功能的 S2L 版本中，只需执行：

```bash
sudo s2l kernel-upgrade
```

也可在菜单选择 **12**。脚本自动检查系统、空间、软件包状态和 GRUB，备份启动配置至 `/var/backups/s2l-kernel-*`，安装 HWE 内核并核验启动文件、PPP/L2TP/TUN 模块。保留旧内核，不调用服务重启或修改 S2L 配置；重复执行会复用已准备好的新内核。

看到“新内核已准备”后，确认主机商控制台可用，等允许断网时**单独执行** `sudo reboot`。重连后检查 `uname -r` 和实际 L2TP 上网。脚本不会自动重启，也不需要关闭本地 iWAN；服务器重启仍会断开 SSH/L2TP。已有 S2L 不必重装。

旧版 CLI 没有此命令时，可在包含此功能的已审阅源码目录直接运行 `sudo python3 script/manage_kernel.py --upgrade`。仅支持 Ubuntu 24.04 generic 内核和标准 GRUB 默认启动项；其他部署停止并提示手动处理。包安装成功不代表真实拨号已验证，失败时不要重启。

### 更新 S2L 应用

## 网页 HTTPS（公网 IP）

新安装自动完成以下步骤。已有安装可在放行指定 HTTPS 端口后，于项目目录执行：

```bash
sudo bash script/setup_https.sh 服务器公网IPv4 8443
s2l 1
```

使用 Nginx 和包含服务器 IP 的自签证书，管理地址为 `https://服务器IP:8443`；后端仅监听本机。浏览器会提示证书不受信任，请核对安装输出中的 SHA-256 指纹后手动信任或导入 `/opt/s2l/tls/self-signed.crt`，不要分享私钥。

无需 TCP 80、证书申请或公网证书续期任务。证书有效期 365 天，到期前重新执行上述命令；有效期不足一天时重新生成证书。已有 HTTPS 安装省略端口参数会保留当前端口，切换证书时保留账号、运行数据和后端端口。配置失败时尝试恢复原配置；恢复失败时，需通过 SSH 或供应商控制台检查备份并处理。

HTTPS 端口可通过网页“系统设置 → HTTPS 管理端口”或 `s2l 9` 修改；保留内部后端端口与证书，更新管理 URL，Nginx 配置校验或重载失败时尝试回滚。

### 卸载

执行 `sudo s2l uninstall --dry-run` 只读检查默认受管安装；执行 `sudo s2l uninstall` 或菜单 **13**，输入 `UNINSTALL` 确认。这会中断受管 VPN 连接。请使用公网 SSH 或云控制台；检测到 SSH 经 PPP／映射 TUN 时会拒绝操作。取消或输入结束不会修改设置。

停止服务并确认 PPP/TUN 已结束后，移除程序、账号、节点密码、证书、受管服务、HTTPS 站点、PPP 文件、路由／防火墙规则、诊断命名空间及运行数据。同时删除干净的默认 `/opt/src/s2l` 源码和已识别的 S2L 升级、内核准备及卸载备份。未知文件、已修改源码或自定义部署会停止自动删除；预览会列出源码／备份路径。停止服务前建立私有恢复备份，失败时保留，**残留检查通过后删除**。需要保留的数据请先另存。

新安装会记录依赖归属。旧版升级若没有记录，会依据受管 S2L 配置及系统包数据库中的原始配置摘要补建待核验清单。卸载时重新核对配置、运行进程、已配置服务和软件包反向依赖关系，清除独占的 VPN 组件与已识别的独立 sing-box 程序；共享或无法识别的组件保留并说明原因。PPP 或 IPsec 库被共享，不会阻止清理其他独占组件。已有记录不覆盖，缺失记录也能在卸载时核验；核验不需要下载软件包。Nginx、Go／构建工具、系统内核、SSH 设置、其他站点／规则和共享系统日志保留。删除 S2L 的 sysctl 文件，但不立即改动内核当前值，主机设置另行审阅或重启。系统日志仍可能含历史 S2L 事件，不会清空其他服务的日志。

失败会停止后续删除并保留恢复数据，服务可能保持停止，需要人工恢复；不要直接重启 PPP。本命令不操作本地路由器或 iWAN，提示沿用面板语言。成功前核对文件、服务、规则、路由及隧道接口，成功卸载后可重新安装。

例如修改密码：执行 `s2l` → 输入 `7` → 输入两次新密码。操作后按回车返回菜单，输入 `0` 退出。

修改管理账号、密码或网页端口时留空取消；管理账号或 HTTP 后端端口变更会重启 S2L，短暂中断拨号连接，启动失败时尝试恢复原配置；HTTPS 端口变更只重载 Nginx。用户名允许字母、数字、`.`、`_`、`-`，密码还允许 `@`、`+`。修改账号密码后重新登录；先放行新网页端口，再修改并使用新端口访问。

修改 SSH：先放行新 TCP 端口，执行 `s2l` → 输入 `10` → 输入端口 → 输入 `yes`。脚本备份 SSH 配置，执行 `sshd -t` 并检查新端口监听，失败时尝试恢复；兼容普通 SSH 服务和 Ubuntu `ssh.socket`。新端口应用后，在另一终端执行 `ssh -p 新端口 用户名@服务器IP` 验证成功，再关闭原连接。备份位于 `/opt/s2l/ssh-port-backup.json`。

命令路径：`/usr/local/bin/s2l`；配置助手：`/opt/s2l/manage_config.py`。

## 故障排查与移除

```bash
sudo systemctl status s2l xl2tpd nginx --no-pager
sudo journalctl -u s2l -n 80 --no-pager
sudo nginx -t
sudo ss -lntup
ip rule show
ip route show table all
```

网页失败查地址、指纹、Nginx、防火墙和安全组，不要改为公开后端。映射失败查页面错误、TUN、sing-box、上游及 系统设置中开启 Debug 后导出的日志 ZIP。拨号失败查账号密码、模式、端口、NAT、xl2tpd 与启用时的 `s2l-ipsec` 日志；拨号成功无流量查子网冲突、策略路由、DNS 和上游。

`running` 不代表端到端验证成功，应从实际客户端检查出口、DNS、IPv6 处理及失败行为；SOCKS5 本身不加密，UDP 能力取决于上游。测速经所选上游联系 Cloudflare，会消耗流量，并非完整 L2TP 路径测试。

TG、微信或网页图片加载失败时，先查看失败请求及映射的 TCP/UDP/DNS 健康状态。S2L 保留客户端选定的目标 IP，避免嗅探域名覆盖图片 CDN 地址；在 `mangle/FORWARD` 对 PPP 两个方向的 TCP SYN 默认钳位 MSS 为 1200，降低隧道分片风险。默认主动拒绝非 DNS UDP，53 端口 DNS 接管后经 DoH/TCP 转发；仅支持 UDP 的业务需支持 UDP 的节点。自动 DNS 模式会在单次 DoH 查询失败时尝试 TCP DNS；连续两次主解析失败后优先使用 TCP DNS。每 30 秒最多在后台复用一次实际查询复查 DoH，连续两次成功才切回；后台复查不会阻塞正常的备用查询；请求取消不计为上游故障。无需重启 sing-box。可选择仅 DoH 或仅 TCP DNS；健康检查也只探测所选方式。

升级服务重启时自动恢复原运行映射并生成新配置，并重新拨号、重建应用连接；这些操作会中断该映射。可用 `sudo iptables -t mangle -S FORWARD` 检查 `s2l-tcpmss` 规则。若仍失败，对比同一失败图片域名经 SOCKS5 的访问结果与客户端结果，结合 系统设置中开启 Debug 后导出的日志 ZIP 区分上游、DNS 和 L2TP 路径问题。

分享日志前删除秘密，勿清空主机防火墙排障。SSH 修改失败时保留原连接，使用供应商控制台等授权救援方式。卸载请使用上方的确认流程；共享资源及自定义部署需先核对归属。


## 映射参数、Debug 与故障恢复

编辑映射时可设置 MTU（1280–1400，默认 1400）、TCP MSS（536 至 MTU-40，默认 1200）、接口队列长度（100–10000，默认 1000）、UDP 策略、DNS 模式及自定义 DoH/TCP 端点。旧数据中缺失字段自动采用默认值。运行中先停止映射再修改；MSS 规则仅匹配对应子网和 PPP 方向。PPP 已连接接口会在独立本地检查中按对端地址应用 MTU、队列和接口级 rp_filter，通常在下一个 5 秒检查周期生效，繁忙恢复时可能延后。PPP MRU 仍为 1400。

UDP 默认主动拒绝非 DNS 请求；可按需允许 UDP 或仅拒绝 UDP/443。允许不代表节点具备 UDP 能力。

每条映射有独立的 TCP 回环解析器，远端 DoH 和 TCP DNS 均经同一 SOCKS5，默认使用 Cloudflare DoH 和 Google TCP DNS。自定义端点格式及 PPP DNS 下发见[客户端接入指南](clients.md)。本地监听仅接受 loopback，sing-box 的专用 DNS 出站固定指向该监听；普通流量仍只能经代理。有效 NXDOMAIN 不触发切换，超时、SERVFAIL、REFUSED 或无效响应触发备用尝试。备用仍失败时返回 SERVFAIL，不回退到服务器直连 DNS。缓存由 sing-box 管理，运行监控显示实际解析器、备用成功次数和最终失败次数，探测列保持独立含义。

网络测试支持独立的 HTTPS 目标检测，结果不回写自动健康状态。需要排查时在系统设置开启 Debug，复现实际客户端问题，再查看时间线分析或导出 ZIP。默认关闭，不保存排障日志或资源采样。详情见 [Debug、备份回滚与恢复熔断](../../DEBUG-AND-STABILITY.zh-Hans.md)。

本地进程与 TUN 检查每 5 秒调度，使用独立于上游探测的四个工作槽；恢复失败按 5–60 秒基础退避并加入抖动；10 分钟内最多 3 次，耗尽后冷却 5 分钟试探，连续稳定 2 分钟重置预算。各映射使用独立生命周期锁，停止、删除和恢复互斥；状态查询不持有耗时操作锁。状态写入仍与生命周期操作协调，防止修改恢复中的配置；过期探测结果会被丢弃。

启停涉及共享的 xl2tpd 配置，因此配置变更到运行状态提交作为一个串行事务执行，避免同时启停多条映射时覆盖其他线路；状态查询和上游探测继续独立运行。文本批量导入更新已有映射时保留 MTU、MSS、队列、UDP 和 DNS 参数，JSON 导入仍使用提交的参数。状态文件先写入独立临时文件并同步，再替换原文件；失败恢复内存状态并清理临时文件。

账号增删及仅注释变化不重启 xl2tpd。若检测到真正的全局配置变更且 xl2tpd 正在运行，会拒绝覆盖并提示维护；在维护窗口先停止 xl2tpd，再重试启动映射。新 PPP 会重新读取账号文件；已停止映射的旧 PPP 受阻断规则保护，不会使用主机出口。

Debug 日志仅保留在有界内存，S2L 重启清空，不再创建 sing-box 日志文件。进程重启后分类计数重置，退出次数在同一 S2L 进程内累计。运行监控显示接口丢包/错误以及日志中超时、连接拒绝、TLS 错误分类；这些是日志计数，不等同于失败请求数。接口统计读取失败会明确显示。

## 检测与升级

首次启动备份并迁移已有映射为主动拒绝 UDP、DNS 自动 DoH/TCP；停止的映射保持停止。恢复旧备份不会回退安装迁移标记，后续策略不会被重启覆盖。升级验证等待原运行映射本地恢复，上游不可用不会单独触发程序回滚；首次恢复失败进入限次重试。每 30 秒核验并修复路由、阻断规则、NAT 和 MSS。

允许 UDP 的映射在 UDP 不支持或连续不可用后每 10 分钟复测；拒绝 UDP 的映射跳过自动 UDP 检测。相同节点凭据、DNS 模式及端点的自动探测短期复用；手动节点检测仅回写 TCP/UDP 及相符的默认 DNS 健康结果。Debug 记录协议变化及最近 256 条连接观察、20 项失败目标；日志不代表传输成功率或完整抓包，NAT 后不能识别原始电脑。


## 分层检测与监控历史

固定 SOCKS5 出口和已配置的 UDP 策略保持不变。节点 UDP 能力独立展示；映射选择拒绝 UDP 时，节点不支持 UDP 不再单独导致映射降级。HTTPS 检测保留失败阶段、HTTP 状态码、耗时及分目标结果；403、429、5xx 表示目标限制或服务异常，不归为代理认证失败。

映射转发实测创建临时隔离入口，通过现有 PPP 入站阻断、策略路由和 TUN 发送 HTTPS，不修改永久规则，也不包含 L2TP 认证。需要 Linux、root、curl，以及至少 /29 且有空闲测试地址的子网；/30 映射仍可正常使用，但不支持该模拟实测。节点与映射分别观测出口 IP；动态出口池可能导致 IP 不同，不能单凭此确认串线。测试支持取消，启动时回收已退出进程遗留的诊断命名空间。

PPP 会话显示接口、对端隧道地址、实际 MTU、计数和首次观测时间；缺少可验证 PPP 事件时，首次观测不等于拨号时间；会话数量也不等于 NAT 后电脑数量。采集失败时保留上次快照并显示提示。

运行历史独立于 Debug，按 5 分钟汇总最近 24 小时，约每分钟保存至 `data/health-history.json`。仅统计已完成探测，未采样不计为离线；接口计数重置不产生虚假流量峰值。出口变化仅来自成功的映射实测。历史不保存密码或原始目标网址；Debug 仍默认关闭且有界。

## 运行事件与可选限额

运行快照共享 5 秒，接口返回采集时间。PPP 采集失败不会阻止独立的防火墙规则核验。TCP 探测按节点凭据共享，DNS 按节点凭据、模式及端点地址共享；UDP 保留独立低频检测。

受管 pppd 上下线脚本通过仅 root 可访问的 Unix socket 上报事件，并保留系统原有脚本。新拨号显示真实连接时间；单独断开会话前核验接口、对端地址和进程身份。服务启动前已有的会话保留首次观测时间，缺少可验证事件时不能直接断开。不确定的断线原因明确保留为未知。

监控页保存最多 500 条故障事件和 1000 条操作记录，支持同节点、多节点关联。多节点异常仅提示公共链路待核验。私有文件 `operations.json` 包含可选通知凭据，应妥善保护。通知默认关闭；启用后向管理员配置的 HTTPS Webhook 发送事件，可设置 Bearer Token、维护静默；发送冷却为 1 分钟，每批发送最多尝试 5 次。

映射上传、下载限额单位为 Kbit/s，TCP 连接上限按整条映射合计，0 表示不限。固定对端地址的账号只允许一条 PPP 会话，仅拒绝超限的新会话；旧值为 0 或大于 1 也不解除此限制。上传使用 TBF 整形，下载使用入口 policing，超额可能丢包。限额不改变固定出口、DNS 传输或 UDP 策略。连接详情通过每个 sing-box 的鉴权回环接口按需读取，最多展示 500 条，不写入历史。

保存配置前预览变更字段和影响范围，不显示凭据值；版本校验阻止旧页面覆盖新配置。运行参数修改仍需先停止映射，自动备份可用于恢复。分组筛选可与现有批量操作配合。鉴权接口 `/api/metrics` 提供运行指标，不将目标地址用作标签。

传输质量检测默认交替请求 1 KiB 和 256 KiB，共 8 次，显示首字节、总耗时、提前断开、中位数及 P95。目标可能忽略 Range；达到读取上限不等于完整下载或 MTU 已验证。TCP 重传及 conntrack 数据为全机统计。

通知编辑使用版本校验，避免旧页面覆盖。更换 Webhook 地址时，未重新填写的旧令牌会清除。采集未知和映射停止不会被当作已确认恢复。

## Google 专项与线路对照

节点的“网络测试 → Google 专项”按需检查八个代表性服务地址，不加入自动健康轮询。可选另一个节点同时检测，或导入上一次导出的专项 JSON 对比历史线路；导入限 512 KiB，不会执行请求或改变配置。结果仅在弹框内保留，可导出。

分别检测经所选 SOCKS 的 DoH A、TCP DNS A 和 AAAA。优先使用 DoH A，失败或无地址时用 TCP DNS A，逐地址检测 TCP、TLS 证书、ALPN 和 HTTP；失败时交错使用 DoH/TCP DNS 结果，最多尝试 3 个 IPv4 地址，保留各次错误。HTTP/2 可协商，重定向不跟随，响应读取有界；401/403/404 不等于出口被封。DNS 地址不同也不等于故障。诊断的 DNS 独立于映射线上解析器；AAAA 结果不代表 IPv6 转发通过。

不会发送 UDP/QUIC，不改变固定出口或 UDP 策略。TCP/TLS 可用只是替代路径证据，手机是否回退仍需客户端复现及 接入网络 ICMP 返回核验。检测不经过映射转发、接入网络 或手机；节点通过不能排除映射连接限额。策略快照显示映射总 TCP 限额、PPP 会话上限和带宽限额；TCP／带宽的 0 为不限，PPP 固定为一条会话，不能用于推断 NAT 后设备数。对“电脑断网手机恢复”可分别导出两次结果对比。

专项检测还会在前后只读采集映射 UDP 拒绝和 TCP 连接限额拒绝计数；检测期间可在手机复现。计数按映射合计，未采集、缺少规则和计数重置分别显示，均不当作零命中。规则命中不证明 ICMP 已返回手机。

## 从 L2TP 内访问管理服务

系统设置的“L2TP 内管理访问”默认关闭。启用时填写服务器实际绑定的 IPv4、允许的 PPP 来源网段（本次排障示例为 `10.0.101.0/24`），以及面板和实际 SSH TCP 端口。页面读取 `sshd -T` 与受管面板配置，再用 `ss -lnt` 核对实际监听，支持填入检测结果；不会修改监听端口或认证。

例外只作用于 PPP 入站到本机的指定 IPv4/来源/端口，不改 FORWARD、固定出口或 UDP 策略，IPv6 仍保持原阻断。更新规则通过 iptables-restore 原子提交；关闭或缩小例外可能中断当前管理连接。管理认证必须启用。公网 IP 若由云平台 NAT 到私网、未绑定本机，需先核对地址及路径；本功能不代替云防火墙、Nginx 或 SSH 监听配置。规则允许后，原始管理目标留在本机处理，不走 SOCKS。


## 登录、语言与 TCP 优先

管理页提供英文、繁体中文和简体中文；语言选择保存在服务器配置中，并缓存于浏览器；服务重启或清除浏览器缓存后仍可恢复。顶部保留语言与帮助，退出登录位于顶部最右侧。表单登录由后端校验现有管理账号，不在浏览器存储密码。会话 Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下启用 Secure；会话最长 12 小时、空闲 30 分钟失效。退出、修改账号或服务重启会使会话失效。登录连续失败会暂时限流；脚本统一通过 JSON 登录接口获取会话；升级自检会在本机登录，完成后销毁会话。

管理例外地址可从本机 IPv4 列表选择。当前访问 IP 经服务器确认属于本机时优先带入；只有一个本机地址时自动带入；多个地址时由用户选择。公网 NAT 地址需单独核对，不会自动启用管理例外。

Google HTTPS（类型 65）DNS 记录经固定节点通过 DoH/TCP 原样转发，不再合成空答案；UDP 拒绝策略保持不变。Google 专项检测会单独查询运行中映射实际 DNS TCP 监听器的 A、AAAA、HTTPS 记录，再使用该解析结果经同一节点检测 TCP/TLS。上游 HTTPS 空答案属于正常结果。这些服务器侧检测不代表手机、PPP 转发、客户端 QUIC 回退或账号登录正常；需要结合映射转发检测与实际客户端验证。映射停止、不可用或检测取消时不会显示为正常。

## 网页更新故障处理

网页更新使用独立 systemd 任务，无登录环境时会为 Go 提供临时构建缓存与工作目录，完成后清理。失败状态保留阶段、退出码和脱敏分类（缓存、工具链、磁盘或下载），不保存原始命令输出。编译阶段失败通常不会进入停止服务和安装步骤；最终以任务状态和服务状态为准。

配置备份支持单份删除，以及保留列表中最新一份、清理旧备份；仅删除所选配置备份，不修改当前配置或系统升级备份，删除前需确认。监控宽表支持横向滚动，手机默认卡片，可切换表格视图。升级运行时每秒刷新状态，收起面板后继续跟踪；空闲且面板展开时每十秒刷新。已安装构建的版本、提交、本地修改状态及随程序提供的说明，与最新发布说明分别展示；源码构建不会冒充稳定版。

## 轻量巡检与按需观测

本地存活检查只读，不对健康接口执行启用操作。已确认缺失的路由、防火墙、MSS 或已配置限速规则原位修复，不清空路由表、不重启正常进程；权限、锁冲突、超时或无效快照只报告检查失败，失败检查按 5–60 秒退避。健康上游每 45–55 秒检查，启动和故障确认保持快速重试。固定出口、DoH/TCP、UDP 主动拒绝和 IPv4/IPv6 防泄漏保护保持。

拒绝 UDP 的映射不自动探测 UDP，界面显示“按策略拒绝”；手动协议检测仍可测量节点能力。DNS TCP 连接池每条映射最多并行 4 个连接，失效的空闲连接仅重试一次，DoH 支持 HTTP/2 复用。移除全流量嗅探，53 端口 DNS 仍经固定代理解析；HTTPS DNS 记录正常透传。进程固定使用 warning 日志级别，Debug 仅临时收集有界内存日志。

映射的“连接观测”默认关闭，可在停止映射后于高级选项启用；连接列表和单连接关闭仅对已启用的映射可用。既有限速与连接上限保留；固定对端账号仅允许一条拨号会话。Google 专项每个所选节点检测一条映射，可指定映射；检测不持有生命周期锁，映射被替换时结果作废。监控折叠后停止其轮询，后台页面暂停普通轮询，执行中的升级继续跟踪。

## 安装预检与恢复

安装使用专用 Ubuntu/Debian、systemd 主机。部署前检查 TUN/PPP/L2TP、防火墙权限、TCP 8080 与 UDP 1701；Ubuntu 缺少模块时安装与运行内核匹配的模块包。拒绝覆盖已有 PPP 账号、会话和运行中的隧道服务。Go 至少 1.22，缺少时依据官方稳定版元数据下载并校验 SHA-256；sing-box 仅接受已验证的 1.11.15，下载文件也核对摘要，部署前检查实际生成的配置。

首次安装在 `/var/lib/s2l-install` 保留私有事务日志。部署失败时恢复受管文件、服务和网络设置，依赖软件包保留；强制中断后重跑会先恢复未完成事务。目录所有权改变或 PPP 进程仍存在时，停止自动恢复并保留保护规则供人工检查。成功需要通过 xl2tpd、S2L、HTTPS 设置和本机认证 API 检查；已成功安装仍使用升级流程。

映射仅接受规范的 RFC1918 IPv4 网段，至少容纳两个对端地址，排除 172.19.0.0/16。启动前检查宿主机网段、接口、路由表与规则优先级冲突；清理仅删除本映射的精确路由，不清空整表。同账号仅允许一条 PPP 会话，旧 max_sessions 为 0 或大于 1 也不绕过保护；网关仍可让多设备共用一次拨号。

CI 启动全新 Ubuntu 24.04 与 Debian 12 amd64 QEMU 虚拟机，验证不兼容依赖拒绝、安装失败恢复、强制中断恢复、真实 systemd、PPP 和故障注入，再重启整个虚拟机并重测。ARM64 仅增加交叉构建，不代表所有发行版／内核或 ARM64 环境均完成实机验证。

全新系统测试还验证两个网关以独立账号、独立映射共用同一 SOCKS 节点：并发转发、重复账号拒绝、上游中断防泄漏，以及单映射修复和停止不影响另一映射；整机重启后重复执行。

安装预检拒绝存在已知 PPPoL2TP 崩溃回归的 Ubuntu 6.8.0-146-generic 与 6.8.0-147-generic（Ubuntu 缺陷 2169477）。首次安装的自动内核准备流程见上文；现有生产主机使用手动流程。完整虚拟机测试会检查内核准备、人工重启后继续安装的路径；无已知问题的镜像直接继续，拨号测试运行于实际启动的内核。
