先阅读[法律与合规说明](legal.md)。普通 L2TP 不加密；管理 HTTPS 不保护隧道流量。保留安全更新，等待软件包管理锁释放，不建议仅为安装而长期关闭自动更新。使用专用主机，以 root 权限执行脚本前审阅代码，现有安装不要重跑安装程序。

## 安装与管理

新安装优先使用下方一键脚本。执行前审阅脚本；其默认获取 `main` 分支，并以 root 执行下载代码。安装会修改系统软件包、转发、PPP/L2TP、防火墙与服务。需要从已审阅源码工作副本安装时，参阅[开发指南](development.md)；现有安装请使用下方更新流程。

安装：

```bash
curl -fsSL https://raw.githubusercontent.com/lucaswren/s2l/main/script/remote_install.sh | sudo bash
```

新服务器安装会**自动启用 HTTPS**，默认使用有效期 **365 天** 的自签证书，无需申请公网证书。访问管理界面需放行 HTTPS 管理端口；实际拨号还需按所选模式放行隧道端口。成功后显示 `https://服务器IP:端口`、管理账号与 **16 位随机密码**。HTTPS 管理端口随机选择 **10000-60000** 范围内的空闲端口，内部后端固定监听 **127.0.0.1:8080**，SSH 端口保留现有设置；自定义密码至少 **12 位**。

公网 IPv4 默认自动识别；需指定时，将安装命令末尾的 `sudo bash` 替换为 `sudo env PUBLIC_IP=服务器公网IPv4 bash`。后端端口无需指定，也无需对外放行；HTTPS 端口不能使用 8080。使用 `HTTPS_PORT` 指定 HTTPS 管理端口，例如：

```bash
curl -fsSL https://raw.githubusercontent.com/lucaswren/s2l/main/script/remote_install.sh | sudo env HTTPS_PORT=8443 bash
```

请提前放行 TCP 8443；不指定时，安装过程显示随机 HTTPS 端口，需放行后才能访问。

1. 使用安装时显示的 HTTPS 地址登录。
2. 添加 SOCKS5 节点，创建映射，启动至 `running`。
3. 客户端选择 L2TP，填写服务器 IP 和映射账号密码；默认不启用 IPsec。

节点列表点击“上下行测速”，分别显示下载、上传速度与连接延迟。测速由服务器经所选 SOCKS5 节点访问测速站，默认每个方向传输 5 MB；单向失败会保留另一个方向的结果。

网页“系统设置”可修改管理用户名、密码、HTTPS 端口和 SSH 端口，登录后无需再次输入管理密码。新密码至少 12 位，留空则只修改用户名；账号修改立即生效，无需重启服务。修改 SSH 前先放行新 TCP 端口，成功后用 `ssh -p 新端口 用户名@服务器IP` 验证登录。

网页“系统设置 → SSH 登录密码”可修改 root 的 Linux 登录密码，仅允许已登录管理员通过 HTTPS 操作，确认新密码即可，无需再次输入管理密码。支持生成 16 位随机密码，手动密码至少 12 位（最多 128 位可见 ASCII 字符）。修改后保留原 SSH 连接，在新终端验证登录；此操作不启用密码登录、不解除账号锁定，也不修改网页管理密码。

网页“系统设置”可启用 **L2TP/IPsec（IKEv1 + PSK）**，适用于支持该模式的 L2TP 客户端。密钥至少 12 位，所有映射共用；留空保留现有密钥，列表不会返回密钥。启用前放行 UDP 500、4500 与 ESP（IP 协议 50），客户端填写相同 PSK；开启后服务器阻止普通 L2TP 接入。关闭后客户端清空 PSK。切换模式或更换密钥需重新拨号。配置或防火墙操作失败时会尝试回滚；若恢复失败，需通过 SSH 检查。备份为 `/opt/s2l/ipsec-backup.json`。与已有 IPsec 服务冲突时会拒绝修改。具体兼容性需按客户端版本验证。

普通 L2TP 需在安全组放行 UDP 1701。管理页面能修改网络并查看凭据，请限制 HTTPS 管理端口的来源 IP。

配置：`/opt/s2l/config.json`；运行数据：`/opt/s2l/data/state.json`。数据文件含代理和拨号凭据，请限制访问权限。

## 网页 HTTPS（公网 IP）

新安装自动完成以下步骤。已有安装可在放行指定 HTTPS 端口后，于项目目录执行：

```bash
sudo bash script/setup_https.sh 服务器公网IPv4 8443
s2l 1
```

使用 Nginx 和包含服务器 IP 的自签证书，管理地址为 `https://服务器IP:8443`；后端仅监听本机。浏览器会提示证书不受信任，请核对安装输出中的 SHA-256 指纹后手动信任或导入 `/opt/s2l/tls/self-signed.crt`，不要分享私钥。

无需 TCP 80、证书申请或公网证书续期任务。证书有效期 365 天，到期前重新执行上述命令；有效期不足一天时重新生成证书。已有 HTTPS 安装省略端口参数会保留当前端口，切换证书时保留账号、运行数据和后端端口。配置失败时尝试恢复原配置；恢复失败时，需通过 SSH 或供应商控制台检查备份并处理。

HTTPS 端口可通过网页“系统设置 → HTTPS 管理端口”或 `s2l 9` 修改；保留内部后端端口与证书，更新管理 URL，Nginx 配置校验或重载失败时尝试回滚。

## 管理命令

服务器终端执行：

```bash
s2l
```

也可直接执行编号，完成后退出，不返回菜单：

```bash
s2l 1   # 显示完整管理 URL 和用户名，不输出密码
s2l 2   # 查看服务状态
s2l 4   # 查看最近日志
s2l 7   # 按提示修改管理密码
s2l 10  # 按提示修改 SSH 端口
```

地址优先使用配置中的 `public_url`（适用于域名或 HTTPS 反向代理）；否则根据监听地址和公网 IP 生成。公网查询失败时显示本机出口地址并提示 NAT 情况。

普通用户会自动请求 `sudo` 权限。输入编号并按回车操作：

| 编号 | 操作 |
|---|---|
| 1 | 查看网页管理地址 |
| 2 | 查看服务状态 |
| 3 | 重启服务 |
| 4 | 查看最近 80 条日志 |
| 5 | 启动服务 |
| 6 | 停止服务 |
| 7 | 修改管理密码（12-128 位，输入隐藏，需再次确认） |
| 8 | 修改管理用户名 |
| 9 | 修改网页管理端口（1-65535） |
| 10 | 修改 SSH 端口（1-65535） |
| 0 | 退出菜单 |

例如修改密码：执行 `s2l` → 输入 `7` → 输入两次新密码。操作后按回车返回菜单，输入 `0` 退出。

修改管理账号、密码或网页端口时留空取消；管理账号或 HTTP 后端端口变更会重启 S2L，短暂中断拨号连接，启动失败时尝试恢复原配置；HTTPS 端口变更只重载 Nginx。用户名允许字母、数字、`.`、`_`、`-`，密码还允许 `@`、`+`。修改账号密码后重新登录；先放行新网页端口，再修改并使用新端口访问。

修改 SSH：先放行新 TCP 端口，执行 `s2l` → 输入 `10` → 输入端口 → 输入 `yes`。脚本备份 SSH 配置，执行 `sshd -t` 并检查新端口监听，失败时尝试恢复；兼容普通 SSH 服务和 Ubuntu `ssh.socket`。新端口应用后，在另一终端执行 `ssh -p 新端口 用户名@服务器IP` 验证成功，再关闭原连接。备份位于 `/opt/s2l/ssh-port-backup.json`。

命令路径：`/usr/local/bin/s2l`；配置助手：`/opt/s2l/manage_config.py`。

## 项目结构与构建

完整开发说明见[架构、配置与开发](development.md)。非 Linux 构建使用替代实现，不能提供实际隧道服务。

| 目录 | 用途 |
|---|---|
| `cmd/s2l/` | Go 程序入口 |
| `internal/` | API、配置、存储、网络、L2TP 和 SOCKS5 管理 |
| `web/src/` | Vue 3 + Element Plus 前端源码 |
| `web/dist/` | 嵌入 Go 程序的前端构建资源，需提交 |
| `script/` | 安装、HTTPS 和系统管理脚本 |
| `deploy/systemd/` | 服务配置 |

修改前端后先构建资源，再编译 Go 程序：

```bash
npm --prefix web ci
npm --prefix web run build
go build -o bin/s2l ./cmd/s2l
```

开发时使用 `npm --prefix web run dev`；API 默认代理到本机 `8080` 端口。
运行配置和数据不提交；本地依赖、IDE 配置与编译产物由 `.gitignore` 排除。

## 备份、更新与恢复

路由表编号限 1–252，253–255 为 Linux 保留表；仅使用专属于 S2L 的表，清理会清空所选表。旧映射若使用保留编号，启动前须修正，勿手动清空系统表。运行文件改存私有 `/run/s2l`（0700），日志为 0600；更新服务单元或由 root 进程创建目录。旧 `/tmp/s2l-*` 不自动迁移，停止旧进程后仅清除已确认属于本项目的残留文件。

更新前记录已部署提交和依赖版本，在维护窗口停止 S2L，备份一致的 `/opt/s2l/config.json`、`/opt/s2l/data/state.json`、旧程序、TLS 私钥、PPP 账号密码、Nginx/systemd 与 SSH/IPsec 修改文件及系统网络配置。限制权限并加密异地备份；`/run/s2l/s2l-*` 生成配置与日志也可能含敏感信息。

在独立工作副本中构建已审阅版本，验证后停止服务，只将构建的 `bin/s2l` 替换到应用程序位置再启动；管理脚本和服务单元的变更应另行审阅后安装。不要把新安装脚本当更新工具：本地脚本拒绝现有配置，远端脚本可能重置源码工作副本。重启后实测映射与客户端流量。失败时停止服务并恢复已验证快照、旧程序及匹配的状态/配置；仅回退程序不一定还原数据格式或系统变更，恢复时保留正确权限和所有者。

## 故障排查与移除

```bash
sudo systemctl status s2l xl2tpd nginx --no-pager
sudo journalctl -u s2l -n 80 --no-pager
sudo nginx -t
sudo ss -lntup
ip rule show
ip route show table all
```

网页失败查地址、指纹、Nginx、防火墙和安全组，不要改为公开后端。映射失败查页面错误、TUN、sing-box、上游及 `/run/s2l/s2l-TUN_NAME.log`。拨号失败查账号密码、模式、端口、NAT、xl2tpd 与启用时的 `s2l-ipsec` 日志；拨号成功无流量查子网冲突、策略路由、DNS 和上游。

`running` 不代表端到端验证成功，应从实际客户端检查出口、DNS、IPv6 处理及失败行为；SOCKS5 本身不加密，UDP 能力取决于上游。测速经所选上游联系 Cloudflare，会消耗流量，并非完整 L2TP 路径测试。

分享日志前删除秘密，勿清空主机防火墙排障。SSH 修改失败时保留原连接，使用供应商控制台等授权救援方式。目前没有完整自动卸载流程；移除须根据备份恢复系统配置并考虑共用服务，不能盲目删除 PPP、Nginx 或防火墙文件。
