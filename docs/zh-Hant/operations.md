## 新安裝

新安裝優先使用一鍵腳本。請使用專用 Ubuntu/Debian 主機，執行前審閱腳本：

```bash
curl -fsSL https://raw.githubusercontent.com/lucaswren/s2l/main/script/remote_install.sh | sudo bash
```

安裝語言統一使用 `--lang`：`en`、`zh-Hant`、`zh-Hans`（預設）。一鍵安裝可在 `sudo bash` 後加 `-s -- --lang zh-Hant`；原始碼安裝使用 `sudo bash script/install.sh --lang zh-Hant`。核心檢查、失敗復原及 HTTPS 設定會沿用此語言；APT、Go 等外部工具保留原始診斷。核心重啟後請使用相同參數重新安裝。

Nginx 已合併至首次相依套件安裝，HTTPS 階段不再重複下載 APT 套件。`[TIME]` 分別顯示相依套件、Go 準備、編譯、憑證及服務驗證耗時。Go 首次編譯也會建置標準函式庫，並顯示套件名稱供查看進度；後續編譯沿用快取。編譯速度仍取決於 CPU、記憶體及磁碟。

修改 SOCKS5 位址、帳號或密碼時，會先列出必須停止的關聯映射，包含等待清理的錯誤狀態映射。表單保留，不會自動停止或重啟映射；名稱與分組可在線上直接儲存。停止列出的映射後返回儲存，再按需啟動。

主推環境維持 Ubuntu Server 24.04 LTS amd64。Debian 12 是相容性測試目標，換系統無法消除首次編譯與套件下載成本。截至 2026 年 10 月，[Debian 12 已進入 LTS，至 2028 年 6 月結束](https://www.debian.org/releases/bookworm/)；[Debian 13 支援期更長](https://www.debian.org/releases/trixie/)，但尚未通過本專案完整虛擬機驗證。

腳本以 root 執行，預設取得最新穩定 Release，明確指定 `BRANCH` 時使用該版本；未指定 `HTTPS_PORT` 時選用隨機空閒 TCP 埠。僅允許可信管理 IP 存取輸出的管理埠。固定埠設定見 README；從已審閱原始碼工作副本安裝的方式見開發指南。既有安裝請使用下方更新流程。

## 上游健康與防洩漏

TUN 回程僅放行到對應網段、經 PPP 介面返回的已建立或相關連線。PPP 中斷導致用戶端路由消失時，遲到回包在轉送層丟棄，不能經伺服器預設出口送出。每個受管 TUN 的回程入口與終止丟棄規則保留至主機重新啟動，映射停止時僅撤銷放行；同一介面反覆重撥不會累計規則。升級清理舊的寬泛放行規則，健康檢查可原位恢復缺失的回程防護。

映射 `running` 與上游健康分別顯示，TCP、UDP、DNS 各自檢查：

| 項目 | 實際探測 | 結果含義 |
|---|---|---|
| TCP | 經 SOCKS5 認證與轉發取得小型 HTTPS 回應；Cloudflare 與 Google 為替代目標 | 可透過上游存取探測網站 |
| UDP | SOCKS5 `UDP ASSOCIATE`，再經協商出的中繼向 `1.1.1.1:53` 或 `8.8.8.8:53` 發送 DNS 資料報 | 回覆須符合來源、查詢 ID 與問題；忽略分片及無效回覆。僅明確的 SOCKS 回覆碼 7 標為不支援 |
| DNS | 經 SOCKS5 探測設定的 DoH，自動模式失敗後探測設定的 TCP DNS；預設為 `https://1.1.1.1/dns-query` 與 `8.8.8.8:53` | 主要 DoH 成功為正常；僅 TCP DNS 成功時顯示「僅備用可用」，探測與實際解析器分開顯示；自動 DNS 模式依真實查詢失敗切換 |

DNS 探測查詢公開名稱 `example.com`，目標流量均使用選定代理，不直接回退至 DNS 目標。建立上游連線時，代理或中繼主機名稱仍可能需要伺服器自身解析器。供應商會收到這些探測連線與查詢；健康檢查不讀取或上傳用戶端 DNS 歷史。

協定首次失敗標為不穩定，連續三次失敗為不可用，連續兩次成功才恢復正常。UDP 明確不支援與 DNS 僅備用可用分開標示。TCP 可用但 UDP/DNS 有問題時顯示部分可用，不判為整個節點中斷；其他成功探測亦避免一概顯示不可用。保留 L2TP，這些協定探測失敗不會觸發 sing-box 重啟。

健康狀態每 45–55 秒檢查，首次與故障確認使用較短間隔，另加探測與排程時間。TCP 失敗按 5、10、20、40、最多 60 秒退避，部分可用時可維持正常間隔。最多同時處理四條映射，每條的協定探測並行且各有時限。拒絕 UDP 的映射跳過自動 UDP 探測；不支援或持續不可用時每 10 分鐘複測。結果不驗證本機 TUN/L2TP 用戶端路徑、所有 DNS 名稱、DNSSEC、QUIC 或所有 UDP 應用程式。

上游中斷時保留 L2TP，已失敗的應用連線須重新建立。sing-box 程序或 TUN 消失時，以受限頻率自動恢復，不停止 L2TP；失敗顯示於健康狀態與服務日誌。目前不自動切換其他節點；更換映射節點前先停止映射。執行中映射使用的節點不可修改連線設定。

S2L 必須使用專用主機：持續防護涵蓋**所有 `ppp+` 介面**。PPP IPv4 僅允許已設定來源子網經對應 TUN 轉發；其他轉發及 PPP 對主機本機的存取均丟棄，明確設定的本機管理存取例外除外，PPP IPv6 亦阻擋。TUN 消失時，終止查找的不可達路由阻止回退至主路由表。停止 S2L 或映射後仍保留阻斷規則，避免既有 PPP 連線由主機出口繞行。`s2l-guard.service` 在 xl2tpd 前安裝規則，失敗時阻止 xl2tpd/S2L 啟動。勿清空這些規則或讓其他防火牆管理器覆寫。用戶端分流與其他網路介面不在伺服器控制範圍內。

## 核心準備與手動升級

首次安裝會檢查執行中的核心與 `/boot` 內已安裝的最高 generic 核心。Ubuntu `6.8.0-146-generic`、`6.8.0-147-generic` 有已知 PPPoL2TP 回歸（2169477）。預設 `S2L_KERNEL_UPGRADE=auto`：只在專用新主機、Ubuntu 24.04、標準 GRUB 預設啟動項下，從系統 APT 來源準備 `linux-generic-hwe-24.04`。既有安裝、活動 PPP／隧道服務、容器與自訂啟動選擇均拒絕自動準備；其他系統版本須手動處理。未命中拒絕清單不代表已驗證相容。

流程檢查空間、套件設定、映像、initramfs、離線 PPP/L2TP/TUN 模組及 GRUB 項目，保留舊核心並抑制 needrestart 自動重啟服務。**退出碼 20** 表示「核心已準備、S2L 尚未安裝」。安裝器不會重啟或自動續裝；確認控制台回復入口與維護時段後，人工重啟、檢查 `uname -r`，再以**原參數**重跑安裝。未重啟時重跑會重用完整核心，不重複下載。不儲存密碼或安裝參數；核心套件不屬於 S2L 安裝回復範圍。`S2L_KERNEL_UPGRADE=off` 關閉自動準備，但不能繞過問題核心檢查。

已安裝此功能的既有伺服器只需執行一條命令，或在選單選擇 **12**：

```bash
sudo s2l kernel-upgrade
```

腳本自動檢查 Ubuntu 24.04 generic 核心、空間、套件狀態及標準 GRUB 預設項，將啟動設定備份至 `/var/backups/s2l-kernel-*`，安裝 HWE 並核驗啟動檔案和 PPP/L2TP/TUN 模組。保留舊核心，不呼叫服務重啟或修改 S2L 設定；重跑會重用已準備完整的新核心。

顯示新核心已準備後，確認主機商控制台可用，於允許斷線時**單獨執行** `sudo reboot`。重連後核對 `uname -r` 並測試實際 L2TP 上網。沒有自動重啟，不需關閉本地 iWAN；伺服器重啟仍會中斷 SSH/L2TP。已有 S2L 不必重裝。舊版 CLI 沒有此命令時，可在包含此功能的已審閱原始碼目錄執行 `sudo python3 script/manage_kernel.py --upgrade`。其他系統或自訂啟動項須手動處理；準備失敗時勿重啟，套件驗證不等於實際撥號驗證。

## 升級

既有預設 `/opt/s2l` 安裝執行：

```bash
curl -fsSL https://raw.githubusercontent.com/lucaswren/s2l/main/script/remote_update.sh | sudo bash
```

升級腳本在建置及停止 S2L/PPP/IPsec 服務前，於受管 Ubuntu/Debian 主機使用 `apt-get` 自動補裝缺少的 `conntrack`。軟體包鎖等待與下載均有時限，命令已存在則略過，不要求升級無關套件。依賴準備失敗時，尚未更換應用檔案或停止服務；處理軟體源／鎖或手動安裝 `conntrack` 後重試。已安裝的依賴套件會保留。

腳本先下載並編譯，再停止服務、於 `/root/s2l-backup.*` 建立私有備份、更新程式與管理腳本及服務單元；原本執行中的 S2L 會驗證本機認證 API。設定、帳號、節點、憑證與連接埠保留，原本停止的服務仍保持停止；執行中的用戶端須重新撥號。

停止服務後若升級失敗，腳本會嘗試還原已備份檔案，保留阻斷規則並讓 PPP 服務保持停止，不會自動恢復撥號；依輸出的備份位置與日誌檢查後重試或手動恢復。下載或編譯失敗不停止服務。腳本不修改 Nginx、SSH、Go 工具鏈或 sing-box；須使用標準檔案路徑與本機後端監聽，自訂部署使用手動流程。

遠端命令以 root 執行下載程式碼，預設跟隨 `main`，請先審閱。若要固定提交，將 `sudo bash` 改成 `sudo env S2L_REF=COMMIT bash`。首次升級後可用 `s2l 11` 呼叫相同流程；已審閱的本機工作副本可直接執行 `sudo bash script/update.sh`。

### 已審閱原始碼與自訂部署

預設受管路徑應從已審閱工作副本執行 `sudo bash script/update.sh`，同步更新程式、管理輔助程式（含 `ipsec_nat.py`）及 systemd 單元。僅更換程式不會安裝新的 IPsec 依賴與鉤子。自訂部署須依完整升級流程調整：先停止 xl2tpd 與 S2L，再停止 IPsec，保留設定與憑據，安裝匹配的輔助程式、單元及防護，再恢復原服務狀態。


## 存取與連線

使用安裝輸出的 HTTPS 網址與帳密；在主機防火牆及雲端安全群組限制管理埠來源 IP，後端 8080 不對外開放。新增授權 SOCKS5 節點與映射並啟動；`running` 不代表端到端驗證成功，須從實際用戶端檢查出口、DNS、IPv6 處理與失敗行為。

普通 L2TP 預設使用 UDP 1701，**不加密**。管理 HTTPS 僅保護網頁/API。IPsec 使用 IKEv1 與共用 PSK，需要 UDP 500/4500，本專案統一使用 NAT-T 封裝，無需單獨放行 ESP，須驗證 NAT 與用戶端相容性。依安全政策選用相容的加密傳輸。

系統設定可啟用 IPsec，PSK 至少 12 字元，所有映射共用；留空保留原密鑰。啟用後阻止普通 L2TP，關閉後用戶端須清空 PSK；切換模式或密鑰後重新撥號。設定或防火牆操作失敗時會嘗試還原；還原失敗時須透過 SSH 檢查。偵測既有 IPsec 服務衝突時拒絕修改，備份中繼資料為 `/opt/s2l/ipsec-backup.json`。

IPsec 防護狀態會核對 INPUT、OUTPUT 專用鏈的完整規則和安全順序；重新套用設定或重啟服務時原子修復兩端防護。OUTPUT 阻擋沒有 IPsec 策略的 L2TP 回包，包括會話隔離輔助程式故障時的回包。同一 NAT 下用戶端可保留來源埠 1701，見[接入要求](clients.md)。

updown 輔助程式在 `/run/s2l-ipsec-nat` 記錄自有規則、串行處理並行通知，並只刪除退役安全關聯的連線追蹤項目；服務啟停清理遺留規則。只有對應安全關聯的隔離規則準備就緒後才接收解密後的 L2TP；早到封包在連線追蹤確認前丟棄，防止重新撥號快取未轉換的對端埠。修復靜態防火牆時保留正在使用的會話放行規則。

專用主機須為 S2L 保留連線追蹤區 20000–65535；內部對端埠不是公網監聽埠，不要在安全群組放行。退役端點進入可重用池，正常重撥不再永久消耗累計 45,536 次的額度。新安全關聯到達時，分配與回收共用程序鎖自動執行：先移除舊關聯的准入、路由規則與連線追蹤，再隔離至少 30 秒；相隔至少 2 秒的兩次閒置觀察必須核對 xl2tpd 全域與 LNS 隧道清單一致，涵蓋尚未完成協商的隧道，並確認無舊端點 socket、L2TP 待處理封包、關聯 XFRM 狀態/策略及連線追蹤區項目。XFRM 使用 reqid/mark 與退役時未標記入站 SA 的 SPI 快照區分連線世代，避免將重用 reqid 的新連線誤判為舊關聯殘留；僅記錄 SPI/位址中繼資料，不保存金鑰。線上用戶端保留原端點與固定 SOCKS5 對應。

45,536 現在是活動端點與尚不能安全回收端點的容量上限，不是累計成功重撥次數。池滿但已有安全候選時，目前撥號會等待短暫的第二次核驗；無法確認安全則拒絕新會話。查詢失敗或 xl2tpd 狀態格式不受支援時保留端點，並在 `/run/s2l-ipsec-nat/state.json` 記錄 `reclaim_error`，不會強制重用。已實測 xl2tpd 1.3.18；要求 root 所有的 `/run/xl2tpd/l2tp-control` 與完整全域/LNS 狀態介面，自訂 LAC 設定保守地不參與回收。回收依新關聯需求觸發，閒置期間保留退役記錄屬正常行為，不能手動刪除執行狀態。舊版狀態缺少退役身分時保留原分配區間，直到兩套協定堆疊均停止；正常升級腳本已按此順序停止與啟動服務，可安全完成遷移。

升級保留 IPsec 啟用及執行狀態，並於服務啟動時更新產生的設定；缺少的 `conntrack` 會依升級章節自動補裝。

Ubuntu 使用套件附帶的 charon AppArmor 設定時，IPsec 啟動僅在 `/etc/apparmor.d/local/usr.lib.ipsec.charon` 增加對 `/opt/s2l/ipsec.secrets` 的讀取權限並重新載入設定，保留其他管理員規則與強制約束。自訂設定不受支援或重新載入失敗時拒絕啟動 IPsec；這條精確讀取規則會保留，供重試及舊版本使用。

測速經所選上游連至 Cloudflare，預設每方向 5 MB，會消耗流量；結果不代表完整 L2TP 用戶端效能，單向失敗仍可能保留另一方向結果。

## 管理

執行 `s2l` 開啟選單，或 `s2l 編號` 執行一次操作；普通使用者會要求 sudo。

| 編號 | 操作 |
|---|---|
| 1 | 網址與帳號，不顯示密碼 |
| 2 / 3 | 狀態 / 重啟 |
| 4 | 最近 80 筆日誌 |
| 5 / 6 | 啟動 / 停止 |
| 7 / 8 | 管理密碼 / 帳號 |
| 9 / 10 | 管理埠 / SSH 埠 |
| 11 | 升級 S2L，保留設定 |
| 12 / `kernel-upgrade` | 準備 Ubuntu 24.04 核心，不自動重啟 |
| 0 | 離開 |

管理密碼 12–128 字元，安裝與 CLI 限制可用字元。CLI 帳密變更重啟服務，可能中斷隧道；網頁變更立即生效，無須重啟，之後重新登入。網址優先採用 `public_url`，否則依監聽與公網 IP 產生，偵測退回本機地址時提示 NAT。

修改連接埠前放行新埠，保留現有 SSH 連線，使用新網址或 `ssh -p 新埠 使用者@伺服器IP` 驗證後才關閉原連線。HTTPS 埠變更重載 Nginx 並保留後端與憑證，驗證或重載失敗時會嘗試還原。SSH 變更檢查 `sshd` 設定與監聽，支援 Ubuntu `ssh.socket`，備份中繼資料為 `/opt/s2l/ssh-port-backup.json`。

網頁 root 密碼功能限已登入管理員透過 HTTPS 使用；接受 12–128 可見 ASCII 字元或產生 16 字元密碼。只修改 Linux root 密碼，不啟用 SSH 密碼驗證、不解鎖帳號，也不修改網頁密碼；須另外驗證登入。

## HTTPS 與備份

路由表編號限 1–252，253–255 為 Linux 保留表；僅使用專屬於 S2L 的表，清理只移除 S2L 精確擁有的路由，啟動時拒絕含其他服務路由的表。舊映射若使用保留編號，啟動前須修正，勿手動清空系統表。執行階段檔案改存私有 `/run/s2l`（0700），產生設定維持私有權限，sing-box 日誌僅存有界記憶體；更新服務單元或由 root 程序建立目錄。舊 `/tmp/s2l-*` 不自動搬移，停止舊程序後僅清除已確認屬於本專案的殘留檔。

既有安裝在放行指定埠並審閱腳本後，可於專案目錄執行：

```bash
sudo bash script/setup_https.sh YOUR_PUBLIC_IPV4 8443
s2l 1
```

信任 `/opt/s2l/tls/self-signed.crt` 前核對輸出的 SHA-256 指紋，勿分享私鑰。自簽憑證不受公開信任，不需 TCP 80 或公開 CA 續期。有效期 365 天；到期前重新執行管理腳本，有效期不足一天時重新產生。既有 HTTPS 安裝省略埠參數會保留原埠，設定失敗時嘗試還原；還原失敗時，須透過 SSH 或供應商主控台檢查備份並處理。

設定為 `/opt/s2l/config.json`，狀態為 `/opt/s2l/data/state.json`；TLS 私鑰、PPP 帳密、Nginx/systemd 與 SSH/IPsec 修改檔也須保護。`/run/s2l/s2l-*` 產生設定檔可能含敏感資訊。限制權限並加密異地備份。

更新前記錄版本，在維護時段備份一致的設定、狀態、舊執行檔與系統網路設定。從已審閱工作副本執行上方升級流程，不要重跑新安裝腳本。啟動後實測映射與流量；驗證失敗時維持 PPP 停止，恢復完整且已驗證的快照，包括匹配的輔助程式、服務單元、程式及狀態／設定。僅回退執行檔不一定能還原資料格式或系統變更，還原須保持正確權限與擁有者。

## 疑難排解

```bash
sudo systemctl status s2l xl2tpd nginx --no-pager
sudo journalctl -u s2l -n 80 --no-pager
sudo nginx -t
sudo ss -lntup
ip rule show
ip route show table all
```

網頁失敗查網址、憑證、Nginx 與防火牆；映射失敗查錯誤、TUN、上游與 在系統設定開啟 Debug 後匯出的日誌 ZIP。撥號失敗查帳密、模式、NAT、xl2tpd 及啟用時的 `s2l-ipsec` 日誌。撥號成功但無流量查子網衝突、路由、DNS 與上游。SSH 變更失敗保留連線並使用供應商主控台等授權救援管道。

TG、微信或網頁圖片載入失敗時，先檢查失敗請求及 TCP/UDP/DNS 健康狀態。S2L 保留客戶端選定的目標 IP，避免嗅探網域覆蓋圖片 CDN 位址；在 `mangle/FORWARD` 對 PPP 兩個方向的 TCP SYN 預設將 MSS 限制為 1200。預設主動拒絕非 DNS UDP，53 埠 DNS 接管後經 DoH/TCP 轉送；僅支援 UDP 的業務需支援 UDP 的節點。自動 DNS 模式在 DoH 查詢失敗時嘗試 TCP DNS，連續兩次失敗後優先使用 TCP。每 30 秒最多在背景複查一次，連續兩次成功才切回 DoH，無需重啟 sing-box。

升級後需重啟對應映射以產生新設定，重新撥號並重建應用連線；這些操作會中斷映射。可用 `sudo iptables -t mangle -S FORWARD` 檢查 `s2l-tcpmss` 規則。若仍失敗，比較同一失敗圖片網域經 SOCKS5 與客戶端的存取結果，並檢查 在系統設定開啟 Debug 後匯出的日誌 ZIP，區分上游、DNS 及隧道路徑問題。

分享前清除日誌中的秘密；勿清空整台主機的防火牆排障。目前無完整自動移除流程，移除須依備份恢復並確認共用服務，不可盲目刪除 PPP、Nginx 或防火牆設定。


## 映射參數與 Debug

映射可設定 MTU 1280–1400（預設 1400）、MSS 536 至 MTU-40（預設 1200）、佇列 100–10000（預設 1000）、UDP 策略、DNS 模式及自訂 DoH/TCP 端點。舊資料自動採用預設值；修改前先停止映射。PPP 依對端位址於本地檢查套用參數，MRU 仍為 1400。UDP 預設主動拒絕非 DNS 請求，也可允許或僅拒絕 443。

獨立 loopback TCP 解析器透過同一 SOCKS5 使用 DoH 與 TCP DNS，預設為 Cloudflare DoH 與 Google TCP DNS；端點格式及 PPP DNS 下發見[用戶端接入指南](clients.md)。NXDOMAIN 不觸發切換，無有效回覆時返回 SERVFAIL，不直連遠端 DNS。監控顯示實際解析器及備用/失敗次數，與協定探測分開。

網路測試支援獨立 HTTPS 目標檢測，結果不回寫自動健康狀態。請開啟 Debug、重現實際用戶端問題，再分析時間線或匯出 ZIP；預設關閉，不保存排障日誌或資源取樣。配置備份保留最近 10 份，回復前必須停止全部映射。自動恢復在 10 分鐘內最多 3 次，冷卻 5 分鐘後試探，連續穩定 2 分鐘重置預算。詳見[穩定性說明（簡體）](../../DEBUG-AND-STABILITY.zh-Hans.md)。

本地存活每 5 秒獨立排程，四個工作槽與上游探測分開，恢復失敗退避 5–60 秒。每映射生命週期鎖協調啟停、刪除與恢復，狀態查詢不等待耗時鎖，過期探測被丟棄。狀態編輯仍與生命週期協調。

啟停涉及共用 xl2tpd 設定，因此設定變更至執行狀態提交會以串行交易執行，避免同時操作覆蓋其他映射；狀態查詢與上游探測維持獨立。文字匯入更新既有映射時保留 MTU、MSS、佇列、UDP 及 DNS 參數，JSON 匯入使用提交的參數。狀態檔先寫入獨立暫存檔並同步，再替換原檔；失敗恢復記憶體狀態並清理暫存檔。

帳號及註解更新不重啟 xl2tpd；真正的全域設定變更在服務執行時拒絕覆蓋，需於維護時段停止 xl2tpd 再重試。Debug 日誌僅保留於有界記憶體，S2L 重啟清空，不再建立 sing-box 日誌檔案。監控增加丟包/錯誤與目前程序日誌分類計數；分類不等同失敗請求數。

僅 DoH 或僅 TCP DNS 模式的健康檢查也只探測所選方式。

## v1.3.1 檢測與升級

首次啟動備份並遷移既有映射為主動拒絕 UDP、DNS 自動 DoH/TCP；停止的映射維持停止。舊備份不回退安裝遷移標記。升級等待原執行映射本地恢復，首次失敗有界重試；每 30 秒核驗並修復路由、防火牆、NAT 與 MSS。

UDP 不支援或連續不可用後每 10 分鐘複測，首次成功後 10 秒確認；相同節點憑據、DNS 模式及端點的探測短期去重；手動節點檢測僅回寫 TCP/UDP 及相符的預設 DNS 健康結果。Debug 增加協定時間線、最近 256 條連線觀察及 20 項失敗目標；日誌不代表實際傳輸成功或完整封包擷取。


## 分層檢測與監控歷史

固定 SOCKS5 出口及既有 UDP 策略保持不變。UDP 能力獨立顯示；選擇拒絕 UDP 的映射不會因節點不支援 UDP 而降級。HTTPS 檢測保留階段、HTTP 狀態碼、耗時和分目標結果；403、429、5xx 屬於目標限制或服務異常，不視為代理認證失敗。

映射實測使用臨時隔離入口，經既有 PPP 入站規則、策略路由及 TUN 發送 HTTPS，不修改永久規則，也不包含 L2TP 認證。需要 Linux、root、curl 及至少 /29 且有空閒測試位址的子網；/30 映射仍可使用，但不支援模擬實測。節點與映射分別觀測出口 IP；動態出口池可能回傳不同 IP，不能單憑此認定路由錯誤。測試可取消，啟動時回收已退出程序留下的診斷命名空間。

PPP 會話顯示介面、對端位址、實際 MTU、計數和首次觀測時間；缺少可驗證 PPP 事件時，首次觀測不等於實際撥號時間；會話數也不是 NAT 後電腦數量。採集失敗保留上次快照並顯示提示。

運行歷史獨立於 Debug，每 5 分鐘彙總最近 24 小時，約每分鐘保存至 `data/health-history.json`。僅統計已完成探測，未採樣不計為離線；計數重置不產生虛假流量峰值。出口變化僅來自成功映射實測，不保存密碼或原始目標網址。Debug 維持預設關閉及有界記錄。

## 執行事件與選用限額

執行快照共用 5 秒並回傳採集時間。PPP 採集失敗不會阻止獨立的防火牆核驗；TCP 按節點憑據共用，DNS 按節點憑據、模式及端點位址共用，UDP 保留低頻檢測。

受管 pppd 上下線腳本透過 root 專用 Unix socket 回報事件並保留系統腳本。新連線顯示真實連線時間；單獨中斷前核驗介面、對端與行程身分。服務啟動前的連線只保留首次觀測時間，缺少可驗證事件時無法直接中斷。無法確認的中斷原因保持未知。

監控頁最多保存 500 條故障與 1000 條操作記錄，支援節點及多節點關聯。多節點異常僅提示共用鏈路待查證。私有 `operations.json` 包含選用通知憑據，應妥善保護。通知預設關閉；啟用後發送至管理員設定的 HTTPS Webhook，支援 Bearer Token、維護靜默、一分鐘冷卻與每批最多 5 次發送嘗試。

映射頻寬單位為 Kbit/s，TCP 連線上限按整條映射合計，0 表示不限。固定對端位址的帳號只允許一條 PPP 會話，僅拒絕超限的新會話；舊值為 0 或大於 1 也不解除此限制。上傳採用 TBF 整形，下載採用入口 policing，超額可能丟包；固定出口、DNS 與 UDP 策略保持原意。連線詳情經 sing-box 鑑權回環介面按需讀取，最多顯示 500 條且不寫入歷史。

設定儲存前預覽變更欄位與影響範圍，不顯示憑據值，並以版本檢查阻止過期編輯。執行參數變更仍須先停止映射，既有自動備份提供復原。分組可搭配批次操作；鑑權 `/api/metrics` 提供執行指標，不以目標位址作標籤。

傳輸品質檢測交替請求 1 KiB 與 256 KiB，預設 8 次，顯示首位元組、總耗時、提前中斷、中位數及 P95。目標可能忽略 Range；達到讀取上限不代表完整下載或 MTU 已驗證。TCP 重傳及 conntrack 為全機統計。

通知編輯使用版本檢查，避免舊頁面覆寫。更換 Webhook 位址時，未重新填寫的舊權杖會清除。採集未知及映射停止不會視為已確認復原。

## Google 專項與線路對照

節點的「網路測試 → Google 專項」按需檢查八個代表性服務地址，不加入自動健康輪詢。可選另一個固定節點同時檢測，或匯入先前匯出的專項 JSON 對比歷史線路（上限 512 KiB）；匯入不執行請求或變更設定。結果保留於彈框，可匯出。

分別檢測經所選 SOCKS 的 DoH A、TCP DNS A 和 AAAA。優先使用 DoH A，失敗或無地址時用 TCP DNS A，逐位址檢測 TCP、TLS 憑證、ALPN 和 HTTP；失敗時交錯使用 DoH/TCP DNS 結果，最多嘗試 3 個 IPv4 位址並保留各次錯誤。支援協商 HTTP/2，不跟隨重新導向，回應讀取有界；401/403/404 與 DNS 地址不同均不等於出口被封。獨立 DNS 不代表映射線上解析器狀態，AAAA 不代表 IPv6 轉發已驗證。

不發送 UDP/QUIC，不改變固定出口與 UDP 策略。TCP/TLS 可用只證明替代路徑，手機是否回退仍需客戶端重現及 接入网络 ICMP 返回核驗。檢測不經映射轉發或手機，不能排除映射限額。快照包含映射合計 TCP 連線上限、PPP 會話與頻寬限額；TCP／頻寬的 0 為不限，PPP 固定為一條會話，不代表 NAT 後裝置數；可分別匯出電腦上線與離線時結果對照。

專項檢測前後唯讀採集映射 UDP 拒絕和 TCP 連線限額拒絕計數，可於檢測期間在手機重現。計數為映射合計；未採集、缺少規則和重置分別顯示，不當作零命中，規則命中不證明 ICMP 已返回手機。

## 從 L2TP 內存取管理服務

系統設定的「L2TP 內管理存取」預設關閉。填寫伺服器實際綁定 IPv4、允許的 PPP 來源網段及面板/SSH TCP 埠。讀取 `sshd -T` 與受管面板設定後以 `ss -lnt` 核對實際監聽，可填入檢測結果；不修改監聽或認證。

例外只作用於 PPP 入站到本機的指定 IPv4/來源/埠，不改 FORWARD、固定出口或 UDP 策略，IPv6 維持阻斷。iptables-restore 原子提交規則；關閉或縮小例外可能中斷管理連線，且必須啟用管理認證。未綁定本機的雲端 NAT 公網 IP 需另外核對路徑，不代替雲端防火牆、Nginx 或 SSH 設定。允許的管理流量留在本機，不走 SOCKS。


## 登入、語言與 TCP 優先

管理頁提供英文、繁體中文和簡體中文，語言選擇儲存在伺服器設定中，並快取於瀏覽器；服務重新啟動或清除瀏覽器快取後仍可還原。頂部保留語言與說明，登出位於頂部最右側。表單登入由後端驗證既有管理帳號，瀏覽器不儲存密碼。工作階段 Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 下啟用 Secure；最長 12 小時、閒置 30 分鐘失效。登出、修改帳號或服務重新啟動會使工作階段失效。登入連續失敗會暫時限流；指令碼統一透過 JSON 登入介面取得工作階段；升級自檢在本機登入，完成後銷毀工作階段。

管理例外可從本機 IPv4 清單選擇。伺服器確認目前存取 IP 屬於本機時優先帶入；只有一個本機位址時自動帶入；多個位址時由使用者選擇。公網 NAT 位址需另行核對，不會自動啟用例外。

Google HTTPS（類型 65）DNS 記錄經固定節點透過 DoH/TCP 原樣轉送，不再合成空答案；UDP 拒絕策略保持不變。Google 專項檢測會單獨查詢執行中映射實際 DNS TCP 監聽器的 A、AAAA、HTTPS 記錄，再使用該解析結果經同一節點檢測 TCP/TLS。上游 HTTPS 空答案屬正常結果。這些伺服器側檢測不代表手機、PPP 轉送、用戶端 QUIC 回退或帳號登入正常；需要結合映射轉送檢測與實際用戶端驗證。映射停止、無法使用或檢測取消時不會顯示為正常。

## 網頁更新故障處理

網頁更新使用獨立 systemd 工作，沒有登入環境時會為 Go 提供暫存建置快取與工作目錄，完成後清理。失敗狀態保留階段、退出碼與去識別分類（快取、工具鏈、磁碟或下載），不儲存原始指令輸出。編譯階段失敗通常尚未進入停止服務與安裝步驟；最終以工作及服務狀態為準。

設定備份支援單份刪除，以及保留列表中最新一份、清理舊備份；僅刪除所選設定備份，不修改目前設定或系統升級備份，刪除前需確認。監控寬表支援橫向捲動，手機預設卡片，可切換表格檢視。升級執行時每秒重新整理狀態，收合面板後繼續追蹤；閒置且面板展開時每十秒重新整理。已安裝建置的版本、提交、本機修改狀態及隨程式提供的說明，與最新發佈說明分別顯示；原始碼建置不會冒充穩定版。

## 輕量巡檢與按需觀測

本地存活檢查僅讀，不修改健康介面。確認缺失的路由、防火牆、MSS 與已設定限速規則原位修復，不清空路由表、不重啟正常程序；權限、鎖定、逾時或無效快照僅報告檢查失敗，按 5–60 秒退避。健康上游每 45–55 秒檢查，啟動與故障確認維持快速重試。保留固定出口、DoH/TCP、UDP 主動拒絕與 IPv4/IPv6 防洩漏保護。

拒絕 UDP 的映射不自動探測 UDP，手動協定檢測仍保留。每條映射的 TCP DNS 連線池最多並行 4 個連線，失效閒置連線僅重試一次，DoH 支援 HTTP/2。移除全流量嗅探，保留 53 埠 DNS 攔截與 HTTPS DNS 記錄透傳。程序採 warning 日誌等級，Debug 僅暫存有界記憶體日誌。

連線觀測預設關閉，停止映射後可於進階選項啟用，以使用連線檢視與單連線關閉。保留既有限速與連線上限；固定對端帳號僅允許一條撥號工作階段。Google 專項每個所選節點檢測一條可指定映射；網路檢測不佔用生命週期鎖，程序更換後結果作廢。監控收合與頁面隱藏時暫停一般輪詢，執行中的升級仍持續追蹤。

## 安裝預檢與恢復

安裝使用專用 Ubuntu/Debian、systemd 主機。部署前檢查 TUN/PPP/L2TP、防火牆權限、TCP 8080 與 UDP 1701；Ubuntu 缺少模組時安裝與執行中核心匹配的模組套件。拒絕覆蓋既有 PPP 帳號、工作階段與執行中的隧道服務。Go 至少 1.22，缺少時依官方穩定版中繼資料下載並驗證 SHA-256；sing-box 僅接受已驗證的 1.11.15，下載檔亦核對摘要，部署前檢查實際產生的設定。

首次安裝於 `/var/lib/s2l-install` 保留私有交易記錄。部署失敗時恢復受管檔案、服務與網路設定，依賴套件保留；強制中斷後重跑會先恢復未完成交易。若目錄所有權改變或 PPP 程序仍存在，停止自動恢復並保留保護規則供人工檢查。成功需通過 xl2tpd、S2L、HTTPS 設定與本機驗證 API 檢查；已成功安裝仍使用升級流程。

映射僅接受規範的 RFC1918 IPv4 網段，至少容納兩個對端位址，排除 172.19.0.0/16。啟動前檢查主機網段、介面、路由表與規則優先序衝突；清理僅刪除本映射的精確路由，不清空整表。同帳號僅允許一條 PPP 工作階段，舊 max_sessions 為 0 或大於 1 亦不繞過保護；閘道仍可讓多裝置共用一次撥號。

CI 另啟動全新 Ubuntu 24.04 amd64 QEMU 客體，驗證不相容依賴拒絕、安裝失敗恢復、強制中斷恢復、真實 systemd、PPP 與故障注入，再重啟整個客體並重測。ARM64 僅增加交叉建置，不代表所有 Debian 或 ARM64 環境均完成實機驗證。

全新系統測試另驗證兩個閘道以獨立帳號、獨立映射共用同一 SOCKS 節點：並行轉送、重複帳號拒絕、上游中斷防洩漏，以及單映射修復和停止不影響另一映射；整機重啟後重複執行。

安裝預檢拒絕存在已知 PPPoL2TP 崩潰回歸的 Ubuntu 6.8.0-146-generic 與 6.8.0-147-generic（Ubuntu 缺陷 2169477）。新主機核心準備及線上主機手動流程見上文。完整虛擬機測試在映像需要時驗證核心準備、退出碼 20、重用與人工重啟；無已知問題時直接繼續，實際撥號測試使用真正啟動的核心。
